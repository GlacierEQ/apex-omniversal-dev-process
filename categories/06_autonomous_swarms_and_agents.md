# 🐝 CATEGORY 06: Autonomous Swarms & Multi-Agent Systems

## 1. Scope & Architectural Mandate
Governs multi-agent dialectic swarms, decentralized agent orchestration, dynamic task decomposition, shared memory graphs, and consensus governance.

- **Domains**: 4-Phase dialectic consensus (Reasoner $\to$ Synthesizer $\to$ Auditor $\to$ Perception), DAG-based plan executors, self-correcting agent loops, multi-agent IPC, decentralized task distribution.
- **Key Constraints**: Zero circular loops / agent lockups, bounded recursion depth, deterministic audit receipts, strict non-clobbering state synchronization.

---

## 2. Polyglot Technology Stack
- **Languages**: Python (agent logic, dialectics, MCP orchestration), TypeScript (real-time agent event loops & webhooks).
- **Protocols & IPC**: Model Context Protocol (MCP), WebSocket event buses, Cap'n Proto zero-copy buffers.
- **Memory & State**: Graph databases (Neo4j), vector stores (Pinecone/Milvus), local SQLite state logs.

---

## 3. Core Invariants & Fail-Closed Boundaries
1. **Loop Termination Invariant**:
   - Every autonomous agent loop must have a strictly enforced `max_iterations` counter and timeout deadline.
   - If an agent does not reach consensus or completion within the budget, it must fail-closed with `ERR_SWARM_MAX_ITERATIONS_EXCEEDED` and yield execution state to human or meta-auditor oversight.
2. **Dialectic Adversarial Audit**:
   - No code, plan, or pull request generated by an agent may be merged or executed without an independent Auditor agent scan passing 100% clean.
3. **Refusal Reason Codes**:
   - `ERR_SWARM_MAX_ITERATIONS_EXCEEDED`: Agent loop reached iteration limit without reaching terminal goal.
   - `ERR_SWARM_CONSENSUS_REJECTED`: Dialectic peer review failed; auditor rejected proposal.
   - `ERR_SWARM_CYCLIC_DEPENDENCY`: Task DAG contains an unresolved cycle.
   - `ERR_SWARM_AGENT_TIMEOUT`: Agent worker unresponsive within heartbeat window.

---

## 4. Stage-by-Stage Implementation Guide

### Stage 0: Contracting
- Define agent roles, authority scopes, available tool catalogs, and dial-back escalation conditions.
- Specify exact consensus criteria (e.g., unanimous agreement among Reasoner, Synthesizer, and Auditor).

### Stage 1: Architectural Modeling
- Define Task DAG state machines: `PENDING` $\to$ `CLAIMED` $\to$ `IN_PROGRESS` $\to$ `AUDITING` $\to$ `RESOLVED` / `REFUSED`.
- Specify agent communication schema (role, message ID, timestamp, cryptographic receipt).

### Stage 2: Pro-Code Implementation
- Implement distributed task queue with heartbeat lease renewal.
- Store step-by-step trajectories in append-only JSONL format.

### Stage 3: Adversarial Verification
- Inject conflicting agent directives; verify the dialectic engine detects disagreement and triggers mediation.
- Simulate an agent hanging indefinitely; assert lease expiration and task reassignment.

## 5. Reference Pattern: 4-Phase Swarm Consensus Engine
```python
from typing import Dict, Any, List
import hashlib
import time

class SwarmConsensusEngine:
    def __init__(self, task_description: str):
        self.task_description = task_description
        self.history: List[Dict[str, Any]] = []

    def run_dialectic(self, proposal: str, auditor_passed: bool, auditor_notes: str) -> Dict[str, Any]:
        # Phase 1: Reasoner & Phase 2: Synthesizer produce proposal
        # Phase 3: Auditor evaluates proposal
        timestamp = time.time()
        
        if not auditor_passed:
            record = {
                "status": "REJECTED",
                "code": "ERR_SWARM_CONSENSUS_REJECTED",
                "reason": auditor_notes,
                "timestamp": timestamp
            }
            self.history.append(record)
            return record

        # Generate cryptographic consensus receipt
        receipt_raw = f"{self.task_description}:{proposal}:{timestamp}"
        consensus_hash = hashlib.sha256(receipt_raw.encode()).hexdigest()

        record = {
            "status": "RATIFIED",
            "code": "SUCCESS",
            "consensus_receipt": consensus_hash,
            "timestamp": timestamp,
            "proposal": proposal
        }
        self.history.append(record)
        return record
```
